# Yearn Protocol Health

Use for a fresh Yearn protocol health snapshot or a repeatable report run. Publish **artifact only** with archive retention. Preserve all existing Sites and prior report URLs. Never deploy or edit the original site to produce a snapshot.

Run from this skill's owning repository, `webops-skills`. The installed Claude Code and Codex skills are symlinks; resolve this directory to find the repository. All runtime dependencies except Bun, authenticated `gh`, optional browser verification, and the repository's `post-artifact` publisher are bundled here. Do not depend on sibling report scripts at runtime. When reuse is authorized, import existing raw evidence and reviewed classifications with their original timestamps and digests; refresh balances, prices, and intervening transactions to the run cutoff. Older report totals are not current observations.

## Run

For an authorized reuse run, use `--import-evidence <prior-evidence-directory> --stage reuse --output <run-directory>`. This copies an allowlisted set of evidence into the run cache, preserves hashes and dates in `imports.json`, and collects only the intervening account history into `delta.json`. Inspect source pricing fallbacks and prior review caveats before reconciling. Import a reviewed yBudget state with `--import-budget <state.json>`. Then `--stage reconcile` runs the bundled supplemental collectors, actual-block audit, matched cohort and debt reconstruction, fee-mint routing, treasury refresh, ledger reads, cash/budget reconciliation and assembly. Every stage uses the fixed cutoff cache; resolve its specific errors and rerun without repeating successful API requests. Review the dated requests in `references/budget-reviews.json` against new approvals on every run; they are historical evidence, not future budget defaults.

1. Read [methodology](references/methodology.md), [input schema](references/input-schema.md), and [source configuration](references/sources.json). Review the treasury address candidates against fresh official deployments and ownership; the registry is a starting scope, not a completeness attestation. Do not copy confidential organizational documents into public outputs.
2. Start `bun run protocol-health --stage preflight`. Default cutoff is execution's current UTC timestamp; keep the printed output directory. Core missing access stops collection. Credential presence is not proof of access. If a variable is missing, ask the user to relaunch through `openv codex` or `openv claude` with the named variable selected; never use `op` or read a secrets file. Follow the exact failures in `preflight.json`. A network/access failure needs repair before retrying.
3. Resume `bun run protocol-health --output <directory> --stage collect`. Each successful request is immutable and cached by cutoff and request parameters. Failed requests are absent and can retry. `collection.json` records secondary gaps. Resolve collector errors and review source freshness, chain coverage and schema changes. Paginated raw records remain local.
4. Review `secondary-candidates.json` for parsed context, activity and traffic aggregates. Reconcile evidence into `<directory>/inputs.json` per the schema. This is an agent research stage, **not an automatic label classifier**: verify vault ownership and wrapper/curation overlaps; reconstruct retained fee splits from events and recipient routing; trace treasury/internal cash transfers; reconcile approved budgets, their periods and revisions. Quantitative inputs must cite cache identifiers. Cache any additional read-only evidence with `Cache.get` from `scripts/io.ts` using the same directory/cutoff. Never mark an unknown core series complete. Protocol-wide reported ledger revenue/costs can support the primary health ratio while a narrower verified vault fee series is explicitly labeled a lower bound. Calendar total revenue and yLockers earned revenue stay unavailable when their timing cannot be reconstructed. State a conservative liquid treasury scope separately from unavailable total inventory valuation. If evidence cannot establish core numbers, report the blocker and retain the incomplete run; do not publish.
5. Refresh all nine panels. Use GitHub, Linear, Plausible, verified partner/organizational evidence, current/historical on-chain records, Kong, Yearn historical pricing, approved budgets and context series. Parse FRED daily CSV and daily stablecoin/DeFi histories into `secondary.macro`; do not use post-cutoff observations. Derive depositor balances and measured flows from event records with matched vault scope; HyperSync may be used where needed with its selected environment credential. If a secondary metric cannot be established, omit it and record why in `collection.json.gaps`; never use zero as a gap. Internal documents support research only: publish aggregates and independently public facts, never document bodies or private URLs.
Keep inline charts on the nine cards. Use measured trends where available and clearly labeled snapshot coverage otherwise; never invent history for missing series. Cards remain clickable without a redundant “Details →” hover prompt.

6. Run `bun run protocol-health --output <directory> --stage validate`, then `--stage render` and `--stage verify`. Inspect screenshots and quantitative commentary. If changing inputs, repeat validation and rendering. `--offline --stage verify` reproduces from saved evidence without API requests. Browser verification requires an installed Playwright module and Chromium; set `PROTOCOL_HEALTH_PLAYWRIGHT_MODULE` to a module path if not globally resolvable.
7. Run `bun run protocol-health --output <directory> --stage publish --publish`. Publication defaults on for `all` and `publish`; `--no-publish` disables it. The command calls `post-artifact`, saves the returned URL before verification, checks the full source-byte hash after accounting for the service’s exact social-preview metadata injection, and exercises the published page. Any other byte change fails verification. Return the URL verbatim. An uncertain upload stops retries to avoid duplicate artifacts. Resolve it against the service before retrying; preserve any known URL.

`bun run protocol-health` executes the stages in order. The first raw-data run stops at reconciliation if `inputs.json` is absent; complete that research stage and resume. This intentional stop prevents inferred financial accounting from being published. `--as-of 2026-10-30T12:00:00Z` selects an explicit cutoff; a resumed directory retains its original cutoff. Never change a directory's cutoff or overwrite a prior publication receipt to refresh a report.

## Local output

The default renderer has no external dependencies. Browser verification requires an installed Playwright/Chromium pair; no npm dependencies are added by this skill.

Default: `$XDG_STATE_HOME/yearn-protocol-health/<UTC timestamp>` or `~/.local/state/yearn-protocol-health/<UTC timestamp>`. `--output` must resolve outside the skill repository, including through symlinks. Keep permissions private and never commit runtime evidence.

A complete run contains `run.json`, `preflight.json`, `cache/`, `collection.json`, reconciled `inputs.json`, aggregate `snapshot.json`, `sources.json`, `methodology.md`, `validation.json`, standalone `index.html`, browser checks/screenshots and `publication.json`. The receipt retains archive retention, cutoff, HTML digest, returned URL and key. Only `index.html` is uploaded. Do not publish raw internal records or credentials.

## Verification

`bun run test:protocol-health` tests accounting and cutoff invariants, missing data, provenance, deterministic offline reproduction, rendering and publication blocking. `bun run install-skills` exports to both agents through the repository workflow. Browser checks exercise desktop/mobile, both themes, all panel drawers, Key Metrics navigation, menu hash Back/Forward/refresh/ESC and dated titles.
